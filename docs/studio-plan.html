How publishing works

Edit, check, publish, live

Every change is saved as a draft first, so nothing half-finished reaches visitors. Publishing refreshes only the pages that use that content.

1 · Edit

Change anything

Text, images, reels, buttons or SEO in a simple form. Autosaves as a draft.

2 · Preview

See it first

Opens the real page with your draft applied, on desktop and phone sizes.

3 · Publish

One button

Or schedule a date and time. Every publish is kept as a version.

4 · Live

Within seconds

The site refreshes those pages immediately. One click rolls back to any earlier version.

How it's built

Small additions to what already runs

Under the hood

  • App: a /studio area inside the same Next.js site, so no new hosting or domain.
  • Login and invites: Supabase Auth, email invite and magic link.
  • Content: Supabase tables for pages, sections, posts, SEO, settings, each with draft and published versions.
  • Media: the existing videos bucket and its folders, plus a photos bucket.
  • Going live: Publish tells Vercel to refresh just the affected pages (on-demand revalidation), so changes show in seconds.
  • Phone app: installable web app (PWA) with a bottom tab bar and lead alerts.

Safety

  • Row level security on every table: visitors can only submit forms, never read them.
  • Version history on every page and post, with one-click rollback.
  • Activity log of every publish, delete and invite.
  • Studio is private: hidden from Google, login required on every screen.
  • Deleted media goes to a 30-day bin before it is removed for good.
